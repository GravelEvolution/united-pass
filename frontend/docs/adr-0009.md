# ADR-0009: Phase 7 policy and audit real API seam

- Status: Accepted
- Date: 2026-08-11
- Depends on: ADR-0004, ADR-0007, backend ADR-0013

## Context

The policy editor, simulator and audit explorer were frozen as mock-backed UI.
Phase 7 supplies the real backend contracts, optimistic versions,
target-bound step-up and durable export states.

## Decision

Policy/audit reads remain Server Component queries with session-cookie
forwarding and `cache: "no-store"`. Draft changes, simulation, publication and
export use the shared browser command client so CSRF and constrained
`X-Reauthentication-Token` handling stay centralized. Every response is
runtime-narrowed before reaching a component.

The editor sends `expectedVersion` on PATCH. Publishing first persists the
latest form as a new draft, then opens the shared password/TOTP/Passkey
reauthentication form bound to `policy.publish + policyId`, and submits that
exact version. A 409 is shown as failure and the consumed grant is never
reused.

Simulation is scoped to the policy detail route and is explicitly a preview.
It never changes runtime permissions.

Audit export opens the shared form bound to `audit.export + audit`, creates a
202 job, polls boundedly, renders pending/processing/failed/completed truthfully
and exposes the backend's same-origin short-lived CSV URL only when completed.
The UI never synthesizes a completed result from current-page records.

## Consequences

- In non-mock mode, policy and audit seams never fall back to fixtures.
- Navigation/capability-based visibility remains UX only; backend checks are
  authoritative.
- Cerbos Admin credentials, policy compiler details and export bytes never
  enter the client bundle.
