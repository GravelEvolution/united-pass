# ADR-0001: 前端路由、服务端边界与可替换数据源

- Status: Accepted
- Date: 2026-08-04
- Owners: United Pass frontend team

## Context

United Pass 前端需要同时承载认证、普通用户账户中心和内部管理后台。当前后端 API 尚未接入，但页面开发需要稳定数据用于结构和交互验证。产品的身份模型要求外部用户转为员工时保留同一稳定用户身份；OAuth Scope 与业务授权策略必须分离。

Next.js 16.3、React 19 和 Semi Design 已被确定为基础技术栈。项目必须避免让临时 mock 侵入页面，也不能把前端权限判断当作安全边界。

## Decision

1. 使用 App Router route group 分隔 `(auth)`、`(account)` 和 `(admin)`，不改变公开 URL。
2. `page.tsx` 和 `layout.tsx` 默认保持 Server Component，仅在表单、移动导航、搜索和提示操作处建立小型 Client Component 边界。
3. 通过 `UnitedPassDataSource` 定义页面所需的查询契约；当前使用 `mockUnitedPassDataSource`，后续 HTTP 实现保持相同接口。
4. 领域类型归属各自 feature；跨多个领域的稳定身份类型放入 `src/types/identity.ts`。
5. mock 只提供静态展示和本地筛选。所有变更按钮明确提示不会持久化，不模拟真实授权成功、会话撤销或管理操作完成。
6. 账户中心和管理后台使用独立共享布局；布局可隐藏不可用入口，但真实鉴权和 ABAC 决策由后端执行。
7. 亮色和暗色模式共享语义化 CSS 变量。没有显式选择时采用系统偏好，显式选择保存到 `localStorage`；固定的初始化脚本在首次绘制前设置主题，并同步 Semi Design 的 `theme-mode`。主题切换控件订阅统一主题快照，动态表达当前状态和目标模式。
8. 管理目录使用 Semi Design Table 通用外壳，每种资源在独立客户端入口中维护列定义与显式可搜索字段。路由只传递当前资源的最小 Mock 记录，避免把七种管理表格分支打入每个页面。

## Alternatives Considered

- 直接在页面中导入 JSON：实现简单，但会把临时数据结构扩散到路由层，替换真实 API 时修改面过大。
- 在 Next.js Route Handler 中搭建完整 mock API：更接近 HTTP，但当前没有端到端网络联调需求，且会制造可被误认为后端安全实现的接口。
- 所有页面统一使用 Client Component：能直接使用 Semi 组件，但会扩大浏览器包与客户端边界，不符合服务端优先原则。
- 引入全局状态管理：当前数据以服务端查询和局部搜索状态为主，没有足够需求支撑新增依赖。

## Consequences

- 页面可以立即用于视觉和信息架构评审，真实 API 接入集中在数据源层。
- mock 与真实协议流程有意保持差距；认证、授权、权限、重认证和敏感操作仍不可用于生产。
- Client Component 只接收可序列化数据，服务端实现不得导入到客户端组件。
- 当 OpenAPI 合同可用时，应以生成类型替换手写传输类型，并在数据源层完成运行时错误归一化。
- 主题偏好不会让根布局读取 Cookie，因此静态预渲染得以保留；固定内联初始化脚本不插入用户数据，但引入 CSP 时需要改为 nonce 或外部脚本策略。

## Implementation Notes

- 路由：`src/app/(auth)`、`src/app/(account)`、`src/app/(admin)`
- 数据源接口：`src/lib/api/united-pass-data-source.ts`
- mock 实现：`src/lib/mock/united-pass-data-source.ts`
- 待接入 API：`docs/api-contracts.md`
- 共享布局：`src/components/layouts`
- 管理目录通用外壳：`src/features/admin/components/management-directory.tsx`
- 管理目录列定义：`src/features/admin/components/tables`
- Semi Design React 19 适配：`src/components/providers/semi-design-provider.tsx`
- 主题初始化与切换：`src/lib/theme`、`src/components/common/theme-toggle.tsx`

## Follow-up

- 与后端确认 API 前缀、分页模型、错误码与 OpenAPI 文档来源。
- 接入服务端会话、OIDC 客户端和后端权限决策。
- API 稳定后添加契约测试和关键认证/授权流程测试。
- 根据权限合同补齐 unauthorized 状态和细粒度操作解释。
- 引入 Content Security Policy 时，为主题初始化脚本设计 nonce 或等价的合规加载方式。
