# DreamUP 小程序活动管理会话授权变更

日期：2026-08-29

## 目的与边界

小程序不再展示管理员安全问题的设置、回答或二次验证流程。该变更只作用于携带有效原生 bearer、精确 `X-UnitedPass-Client: dreamup-miniprogram` 形态且服务端会话记录标记为 `ClientKindMiniProgram` 的 DreamUP 小程序活动管理请求。

浏览器 Cookie 管理端继续使用原有安全问题、durable step-up 和高风险单次授权，不改变官网行为。本次不新增或迁移数据库，不写入 authority 结构，也不修改 DreamUP 官网、代理或其他服务。

## 服务端强制条件

原生小程序的每次活动管理请求仍必须满足：

- bearer 命中 Redis 中的有效原生会话，且认证时间不超过 30 分钟；
- 会话携带的账户安全纪元大于零，并与 authority 的当前安全纪元完全一致；
- 当前用户对精确活动拥有有效的固定角色、角色绑定 ID 和正版本号；
- 能力、资源种类、资源 ID 和活动 ID 通过对象级授权；
- 写请求继续满足 `If-Match`、调用方幂等键、请求体摘要和审计要求；
- 下游断言继续绑定方法、规范路径及查询、正文摘要、活动、角色、角色版本、会话认证时间、授权时间、JTI 与防重放标识。

高风险原生请求不再消费安全问题产生的 token，而是在上述条件全部通过后为单次请求生成密码学随机 `nma_*` 授权 ID，并绑定进现有签名断言。显式提交了旧 token 时仍优先严格消费；无效 token 不会降级到原生会话授权。

## 兼容窗口

服务端暂时保留旧版本小程序使用的三个原生 step-up 路由，使已发布版本在新版采用前不会突然失效。新版客户端不再调用这些路由。确认新版采用率后应单独删除原生 allowlist 中的兼容项；浏览器路由不应删除。

当前断言仍借用字段名 `reauth_grant_id` 承载 `nma_*`，其实际含义是“本次服务端原生会话授权”。这是 P2 语义兼容债，不是权限放宽。后续断言 v2 应引入明确的 `authorization_context=native_session`。

## 失败与回滚

缺少安全纪元读取器、纪元为零、读取失败、纪元漂移、未来认证时间、超过 30 分钟、角色绑定缺失或授权拒绝时，服务端在签名和调用 DreamUP 前失败关闭。

部署不包含迁移。回滚只需把 `moonstone-up-api` 的 `current` 符号链接切回上一 release 并仅重启 `moonstone-up-api.service`；不需要数据库回滚。

## 验证

- 原生普通读取和高风险写入在无安全问题 token 时成功，但必须生成请求绑定断言；
- 纪元缺失、漂移、读取失败、未来/过期登录全部在签名和上游调用前拒绝；
- 显式无效旧 token 不会回退；
- 浏览器原有 step-up 行为保持；
- HTTP 边界只从已验证的服务端会话记录复制安全纪元，不能由请求头提供；
- 原生 bearer 路由 allowlist、方法和路径仍为显式枚举。
